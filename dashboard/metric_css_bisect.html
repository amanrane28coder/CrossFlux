Outcome. Pane A ghosts on specimen 1, pane B does not. The load-bearing change is removing div[data-testid="stMetricValue"] div { display: inline }: Streamlit's screen-reader copy of the value hides itself with overflow:hidden; height:0, and height does not apply to a non-replaced inline box — so forcing every descendant inline puts that copy back into the visible flow. Specimen 3's copy uses position:absolute instead, which re-blockifies and therefore survives; that is why the bug looked intermittent across metrics rather than affecting all of them. The [aria-hidden] / .visually-hidden suppressors in pane B are belt-and-braces on top of that.

Second, independent defect fixed at the same time. Pane A's rules are all scoped to metric-container, a test id Streamlit renamed to stMetric around 1.28 — on a current version most of pane A's styling silently does nothing. Pane B targets both, which is why the label/value sizing also changed appearance when the fix went in.

If ghosting ever returns. Open this file first. If pane A ghosts and pane B is clean, the CSS in app.py has regressed — check that no rule sets display on descendants of stMetricValue. If both panes are clean yet the live dashboard doubles, the cause is not this CSS; the next suspect is the 1 second st_autorefresh at app.py:14 interacting with the raw-HTML blocks, and the thing to capture is a devtools DOM snippet of one doubled metric.

Caveat. The panes here are prefixed with .old/.new for side-by-side isolation, so specificity is one class higher than in the real app; the cascade that matters (the display override versus the hiding utility) is unchanged.
